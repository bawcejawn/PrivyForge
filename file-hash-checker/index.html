    How to verify a download

    1. Find the checksum on the official download page (often labeled "SHA-256" or "checksum").
    2. Paste it into Expected hash. The algorithm is picked automatically from its length, and a pasted line from sha256sum works too — the file name is ignored.
    3. Drop the downloaded file. A green Match means it's byte-for-byte identical to what the publisher released.
    4. If you see No match, download the file again from the official source and re-check before opening it.

    Worked example: one changed letter

    Make a plain text file containing the word hello followed by a line break (6 bytes) and drop it in. With SHA-256 selected, the file hash checker shows:

    5891b5b522d5df086d0ff0b110fbd9d21bb4fc7163af34d08286a2e846f6be03

    Change it to Hello with a capital H and hash it again:

    66a045b452102c59d840ec097d59d9467e13a3f34f6494e539ffd32c1bb35f18

    One letter changed and the whole fingerprint changed. That's what makes a checksum useful: any difference at all, whether a corrupted download or a tampered installer, produces a completely different hash.

    What a hash is

    A cryptographic hash turns a file of any size into a short, fixed-length fingerprint. The same file always gives the same hash, on any computer. You can't rebuild the file from its hash, and it's practically impossible to craft a different file with the same SHA-256 hash.

    Each algorithm has a recognizable length in hex characters: SHA-1 is 40, SHA-256 is 64, SHA-384 is 96 and SHA-512 is 128. That's how the tool recognizes the type of hash you paste.

    Prefer the command line? sha256sum file on Linux, shasum -a 256 file on macOS and Get-FileHash file in Windows PowerShell give the same SHA-256 result.

    Proving a file existed — without sharing it

    Click Proof to download a small receipt with the file's SHA-256 fingerprint, size and time. Keep it with the file. Later, anyone with the original can recompute the hash and confirm nothing changed. For an independent timestamp that doesn't rely on your own records, submit just the hash (never the file) to a public timestamping service such as OpenTimestamps, which anchors it to the Bitcoin blockchain for free.

    Frequently asked questions

    Is my file uploaded?

    No. Hashing uses your browser's built-in Web Crypto engine. The file is read into memory on your device and nothing is sent anywhere.

    Which algorithm should I use?

    SHA-256 is the modern standard. SHA-1 is only for checking older downloads that publish it; it's no longer considered secure against deliberate tampering.

    Does a match prove the file is safe?

    It proves the file is identical to the one the checksum describes. If the publisher's own site were compromised, both could be altered, so take checksums from the official source.

    Is there a size limit?

    Files up to 2 GB. The whole file is read into your browser's memory, so very large files need a device with enough free memory.

    What about MD5?

    MD5 is broken for security purposes and browsers don't include it. If a site only publishes MD5, ask for a SHA-256 checksum instead.
